Halaman 500? Baca log, bukan menebak

Satu kemenangan: dari pesan error kamu bisa menunjuk baris penyebabnya dalam 1 menit.

Kasus nyata barusan: halaman transaksi 500. Dugaan awal "salah konsep Alpine di @click" — ternyata penyebabnya koma ganda di PHP: ?? '-',, 'type' di resources/views/transactions/index.blade.php:55.

Langkahnya (selalu sama)

tail -n 30 storage/logs/laravel.log

Cari baris local.ERROR pertama, baca pesannya sampai kata at ...:

local.ERROR: Cannot use empty array elements in arrays
  at .../storage/framework/views/ca2560....php:54
Potongan pesanArtinya
Cannot use empty array elementsAda elemen kosong di array — curigai koma ganda ,, atau koma nyasar.
storage/framework/views/*.php:54Ini hasil compile Blade, bukan file aslimu. Buka baris 54 di situ, lalu petakan ke .blade.php yang sesuai.

Konsepnya: Blade tidak dijalankan langsung — ia diterjemahkan dulu jadi PHP polos di storage/framework/views/. Jadi error PHP selalu menunjuk file compile; tugasmu menerjemahkannya balik ke Blade. Setelah perbaiki Blade, jalankan php artisan view:clear agar compile lama tidak dipakai lagi.

Benar. Pesan → file compile + baris → baris Blade → perbaiki → view:clear → refresh.
Salah. Menebak-nebak bagian Alpine/JS padahal pesannya jelas menyebut array (PHP).
Sumber utama: Laravel Docs — Error Handling & Logging. Pendamping: cheatsheet modal.

Retrieval check

Q1. Path storage/framework/views/*.php di pesan error adalah…

Belum tepat — file asli berakhiran .blade.php. ❌

Tepat — selalu petakan balik ke .blade.php. ✅

Belum tepat — route cache tinggal di bootstrap/. ❌

Q2 (lisan). Habis edit Blade tapi error lama masih muncul — perintah apa yang dijalankan? (Jawab tanpa melihat: php artisan view:clear.)
